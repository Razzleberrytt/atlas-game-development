# Main World environment production plan

**Roadmap ticket:** BA-013

**Lane:** controlled build-ahead, Main World / Hub Track 1

**Status:** production plan complete; broad environment pass and runtime activation held

**Evidence level:** E1 source/recovered-evidence planning only

**Playable-patch mapping:** Gate 0 audit input; broad production belongs to Patch 0.5

**Runtime behavior:** none

## Decision

The first Main World environment pass will build a compact, readable HubTown
core and its immediate arrival, preparation and expedition-gate composition
before expanding into the large recovered overworld. Production uses bounded,
reviewable kits and semantic streaming groups; it does not restore the entire
1,775-row hierarchy as one scene or treat recovered instance counts as a
performance budget.

This plan turns BA-010's disposition audit, BA-011's dedicated-place/source
boundary and BA-012's stable interaction registry into production units,
quality tiers and provisional admission ceilings. The ceilings protect the
first art pass but are not accepted device evidence. BA-014 owns the repeatable
Studio matrix that measures, lowers or rejects them.

No broad geometry, Terrain, model asset, audio asset ID, Lighting mutation,
streaming setting, bootstrap or Main World runtime is authorized here.

## Playable-patch boundary

[`../roadmap/PLAYABLE-MVP-PATCH-EXECUTION.md`](../roadmap/PLAYABLE-MVP-PATCH-EXECUTION.md)
controls implementation order. Gate 0 runtime stabilization remains active and
MVP 0.1 needs only the smallest coherent preparation/return surface required
for a complete repeatable run. BA-013 must not make the final Main World, this
entire kit plan or BA-014 acceptance a prerequisite for that MVP.

Before Patch 0.5, a bounded item from this plan is eligible only when a
separate current-patch task explicitly needs it and its runtime/evidence gates

and broad Main World environment production stays held. This document exists
now so later art work follows accepted evidence and budgets instead of becoming

## Kit content and variation rules

### Hub and structure modules

Use the visual bible's 4-stud base grid and 8/16/32-stud macro increments for
new modular pieces. Recovered geometry retains its evidence-backed 1:1 world
transform during parity reconstruction; it is not rescaled merely to fit the
grid.

The first civic kit targets these reusable families before one-use decoration:

- floor/deck, edge/railing, stair/ramp and threshold pieces;
- structural supports, canopy/roof pieces and portal/door frames;
- practical lamps with emissive-only and local-light variants;
- broad furniture/utility silhouettes for service identity;
- arrival, fountain/stair and expedition-gate landmark pieces;
- authored prop clusters and cause-based damage/weathering overlays.

Every module declares pivot, forward direction, collision policy, material
family, quality behavior, streaming group and any semantic anchor socket.
Manual edits to scattered copies are prohibited.

### Terrain and route workflow

Terrain advances through four checkpoints:

1. **Envelope:** flat/primitive graybox proves arrival, core loop, sightlines,
   route widths, boundaries and four-player clearance.
2. **Landform:** Studio Terrain establishes authored elevation, drainage,
   water and transition shapes without foliage or hero dressing.
3. **Surface:** approved material families, path edges, erosion and controlled
   breakup are added after navigation/collision review.
4. **Integration:** structures, foliage, VFX and audio volumes are admitted
   against scene budgets and BA-014 captures.

Each Terrain revision requires a manifest containing:

```text
manifest version
world/content ID and coordinate space
repository commit and source place/build identity
authored bounds, origin and voxel-region hash
tool/process and material palette
included regions and known omissions
navigation/collision review status
Studio capture/evidence packet reference
rollback checkpoint
```

The original RBXL remains preservation evidence. Terrain production works in a
new authorized Main World place/branch and never overwrites that evidence.

WorldPath becomes route control data and render chunks. The initial authoring
target is **64–128 studs of route per chunk**, split earlier at a landmark,
branch, elevation transition or distinct streaming dependency. Chunk seams
overlap visually enough to prevent a naked gap, but semantic route continuity
comes from stable IDs rather than both chunks being present forever. Exact
streaming radii remain a measured BA-014 setting.

### Prop and foliage repetition

Props keep the visual bible's three tiers:

- Tier A gameplay props have unique silhouettes, truthful collision and a
  canonical owner before activation;
- Tier B narrative props communicate one authored story idea in a cluster;
- Tier C dressing props reuse atlases/materials and usually have no collision.

One cluster contains one focal object and two to five supporting objects.
Signature clusters do not repeat adjacently. A single camera view may not use
an important story prop as generic filler, and repeated medium props require a
different cluster role, material/damage state or silhouette partner. Random
rotation alone is not accepted variation.

The outdoor family target remains deliberately bounded:

```text
3 tree/trunk families
3 large-root families
4 bush/fern clusters
3 ground-cover clusters
2 hanging-vine families
2 altered-growth families
1 reactive accent family
damaged/dead variants for two major families
```

Close/mid/far representations are produced only where measurement shows value.
Ground foliage never hides low enemies, loot, hazards, prompts or route edges.

## Asset admission ceilings

These are starting ceilings from the visual production bible, not engine
limits or evidence that a dense scene will pass.

| Asset class | Triangle target | Material slots / texture strategy |
|---|---:|---|
| Modular structural piece | 300–5,000 | 1–2; shared 1024 trim/material family preferred |
| Hero landmark | 15,000–50,000 | Split/stream where useful; every extra slot justified by capture |
| Medium prop | 300–3,000 | 1–2; 512–1024 shared atlas |
| Small prop | 50–800 | 1; 256–512 atlas region |
| Foliage cluster | 200–2,000 | 1 preferred; 512–1024 shared family atlas |

An asset below its triangle ceiling can still fail because of transparency,
material count, texture memory, collision complexity, screen density or
animation cost. Hero detail is concentrated near reachable surfaces; distant
mass relies on silhouette and broad value/color blocks.

## Quality-tier and visible-scene ceilings

Counts below apply to optional **Main World ambient presentation visible to one
client**, not combat telegraphs or canonical gameplay state. They are planning
ceilings to be profiled with the full UI and a four-player gathering scene.

| Ambient cost | Full | Reduced | Minimum readable |
|---|---:|---:|---:|
| Visible enabled local dynamic lights | 16 | 8 | 4 |
| Visible shadow-casting local lights | 1 | 0 | 0 |
| Visible ambient particle emitters | 12 | 6 | 0 |
| Estimated live ambient particles (`Rate × max Lifetime`) | 300 | 120 | 0 |
| Client-animated decorative parts | 32 | 16 | 0 |
| Simultaneously audible localized environment emitters | 4 | 2 | 1 |
| Ambient/music beds during steady state | 1 + 1 | 1 + 1 | 1 ambient; music optional |

Brief crossfades may overlap two beds, but the outgoing source must stop and be
released. Full quality uses the approved composition. Reduced quality targets
at most 60% of Tier C dressing/ground-cover density, earlier mid/far LOD,
emissive-only repeated lamps, lower ambient rates and fewer secondary motions.
Minimum-readable retains landmark silhouettes, route edges, interaction forms,
collision and semantic cues while removing optional particles, decorative
motion and most Tier C dressing.

No quality tier may:

- remove or change collision/navigation truth;
- hide an interaction, spawn, return or expedition anchor;
- use stream-out or presentation suppression as gameplay completion;
- remove color-independent route or hazard recognition;
- change server-authored day/night, mission, reward or eligibility state.

## Lighting, VFX and audio profiles

### Lighting

One Main World profile owns `ClockTime`, brightness/exposure, ambient values,
fog/atmosphere, grade and global post effects for its lifecycle. Local landmark
or interaction presentation may add bounded practical lights but may not write
global `Lighting` properties. A source-managed `Sky` or other asset-backed
profile waits for a real, permission-verified asset.

The safe-space look must preserve route and face/interactable readability
without bloom or local shadows. Repeated lamps default to emissive geometry;
the scarce enabled lights are assigned to orientation, depth and focal-service
value. Full, Reduced and Minimum-readable captures use the same fixed cameras.

### VFX and motion

Ambient VFX uses local volumes parented to semantic streaming groups.
Fireflies, smoke, fire and portal motion provide depth or identity; they never
replace a solid landmark, interaction shape or critical tell. Each effect
declares owner, active conditions, quality reductions, maximum rate/lifetime,
pool/scope, stream-out behavior and stop/cleanup proof.

Recovered emitters are rebuilt from supported evidence only after fitting the
visible-scene ceilings. The current operation environment-animation controller's
unretained Workspace connections remain separate lifecycle debt; BA-013 neither
copies nor repairs that active runtime path.

### Audio

The future environment-audio owner creates one approved hierarchy:

```text
AtlasEnvironment
├── Music
├── AmbientBeds
└── LocalEmitters
```

The audio kit defines one base ambient bed per profile, optional music region,
localized one-shots/loops for water, forge, portal, wind and wildlife, and
bounded transition zones. Stable zone IDs survive absent local Instances.
Crossfades are client-owned, duplicate-safe and clean up on place/lifecycle
exit. Audio assets require ownership/permission verification and loudness/mix
review before their IDs enter source.

Environment volume controls remain separable from critical gameplay cues.
Critical information retains visual/text alternatives; ambience may reinforce
meaning but never becomes the only warning, route instruction or interaction
confirmation.

## Streaming production rules

| Semantic group | Production target |
|---|---|
| `main_world.hub_core` | Arrival collision, orientation landmark and required return/interaction forms are ready before character release. Persistent-core status remains a measured candidate, not a default. |
| `main_world.primary_route` | 64–128-stud authoring chunks, split at semantic beats; next-route continuity and HUD fallback are tested when a target is absent. |
| `main_world.resources` | Spatial clusters by authored region; never one model per resource type spanning the map. Presentation streams independently of future gathering state. |
| `main_world.structures` | One coherent authored structure per review unit, split again when it exceeds the hero-asset ceiling or measured transition budget. Never one atomic WorldStructures model. |
| `main_world.atmosphere` | Local volumes/profile data; effects and sounds release references on stream-out and rebind by stable ID on stream-in. |

Every streamable unit has a stable ID, bounds, pivot, source-evidence reference,
content dependencies, optional/required classification, quality behavior and
cleanup/rebind owner. Engine radii, `ModelStreamingMode` and persistent-model
choices are selected only after BA-014 measures representative units.

## Performance targets for BA-014

BA-014 must test a representative four-player hub gathering, the core loop and
a route traversal with UI, audio and all selected environment tiers active.
Provisional pass targets are:

- desktop Full target: median client frame time at or below 16.7 ms and p95 at
  or below 25 ms during steady traversal;
- lowest supported mobile Minimum-readable target: p95 client frame time at or
  below 33.3 ms during steady traversal;
- no post-warmup streaming hitch longer than 100 ms and no visible void,
  collision fall-through or spawn release before required content is ready;
- after a ten-minute traversal and return cycle, environment-owned Instances,
  connections, sounds, emitters and memory return to within 5% of the stable
  post-load baseline after cleanup;
- no static-content replication churn after a semantic group is loaded;
- route, interaction, portal and return meaning remains correct when optional
  models/effects are absent and after they rebind.

Target hardware names, graphics levels, capture duration, MicroProfiler labels,
memory categories and warmup method must be recorded in BA-014. A failure lowers
density/ceilings or splits units; it does not get excused because the asset
passed in an empty test scene.

## Production order and review gates

1. Build an isolated neutral validation scene for kit scale, materials,
   collision, quality tiers and cost.
2. Preview only the arrival/civic/expedition-gate composition from coherent
   recovered groups; keep it unmapped and held.
3. Approve the graybox core loop and Terrain envelope before surface/detail.
4. Build route chunks and selected hero silhouettes; reject dead travel and
   whole-root streaming units.
5. Add reusable prop/foliage/material kits under repetition and admission
   ceilings.
6. Integrate one Main World lighting/VFX/audio profile in the isolated place
   only after concrete owners and verified assets exist.
7. Run BA-014's fixed-camera, traversal, streaming, four-player, low-graphics,
   mobile, memory and cleanup matrix.
8. Only a later playable-patch/gated integration ticket may create or activate the dedicated
   project/bootstrap, record its rollback checkpoint and map accepted content.

Each review unit carries its source paths/IDs, supported-property comparison,
known omissions, triangle/material/texture/collision summary, quality-tier
captures, streaming classification, performance capture and rollback source.
