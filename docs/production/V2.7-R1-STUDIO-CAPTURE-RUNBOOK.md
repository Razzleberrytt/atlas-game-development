This runbook minimizes manual work for the first accepted R1 runtime packet. It does **not** change the build under test.

## Why the helper is safe

`games/living-kingdoms/tools/studio/V27R1Capture.client.luau` lives outside `games/living-kingdoms/src/` and is therefore not part of the Rojo place mapping. It only reads existing attributes and Highlight instances. It does not create, destroy, enable, disable, mutate, or send anything.

## One-player R1 procedure

1. Open the exact canonical artifact in Roblox Studio.
2. Confirm the place is the R1 build identified above.
3. Clear Studio Output.
4. Start one-player Play from a cold client start.
5. In the running **client** context, run the complete contents of `games/living-kingdoms/tools/studio/V27R1Capture.client.luau` from the Command Bar once shortly after the client becomes controllable.
6. Keep playing for at least 60 seconds so normal horde-state publishing occurs. Trigger ordinary enemy hit/kill feedback during the run if possible.
7. Run the same capture script again in the client context.
8. In Output, search for:
   - `HordeNetwork.State`
   - `invocation`
   - `queue`
   - `discard`
   - `[Living Kingdoms] Disabled broad Highlight`
9. Record whether ordinary narrow enemy hit/kill Highlight feedback remained visible and whether any broad blue/yellow world wash appeared.
10. Stop play before changing any source or rollout flag.

## Capture output

Each invocation prints one machine-readable line:

```text
LK_V27_R1_CAPTURE {json}
```

It also prints:

```text
LK_V27_R1_CAPTURE_SNAPSHOT_PASSABLE true|false
```

`SNAPSHOT_PASSABLE` checks only facts available to the capture script:

- early listener bound;
- received message count greater than zero;
- invalid message count zero;
- numeric last revision;
- broad Highlight guard active;
- no still-enabled broad Highlight target matching the R1 guard definition.

It **does not** declare R1 accepted. Queue/discard warnings, startup regressions, visible behavior, exact build identity, and legitimate narrow Highlight behavior still require the operator/runtime observations in the evidence packet.

## Fields captured automatically

The JSON record includes:

```text
listener.bound
listener.messagesReceived
listener.invalidMessages
listener.lastRevision
highlightGuard.active
highlightGuard.rejectedCount
highlightGuard.lastTarget
highlightScan.total
highlightScan.enabled
highlightScan.rejectedInstances[]
highlightScan.stillEnabledBroad[]
```

`highlightScan.stillEnabledBroad` independently applies the same conservative R1 broad-target definition to every enabled Highlight currently under Workspace. A non-empty array is a failure lead and must not be hidden by the guard counters.

## What to paste back into the evidence packet

Keep both `LK_V27_R1_CAPTURE {json}` lines: the first cold-start snapshot and the second 60-second snapshot. Also record:

